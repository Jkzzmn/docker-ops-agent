# F1–F5 개선 구현 결과

대상 기획서: `IMPROVEMENT_PLAN_20261021.md`. API 2.5 / 기존 Supervisor·LangGraph 구조를 유지하며 구현했습니다. 업무 프로젝트의 파일 수정, 컨테이너 기동·재시작, 승인 실행은 수행하지 않았습니다.

라우팅은 규칙 fallback이 아닙니다. 구조화한 LLM 의도를 서버의 scope·allowlist·출처 검사로 제한합니다. education 선택에 실제 설정 파일 참조가 있을 때만 카드 문맥 없는 quality LLM이 조회 요청의 정확한 인용까지 재확인합니다. 인용·파일 참조가 근거로 검증되지 않으면 환경 조회로 바꾸지 않습니다. 명확한 상태 요청에 불필요한 Writer/품질 검증을 붙이지 않습니다.

## 지원 범위와 남는 제한

1. 정적 검토는 문서에 명시한 작은 규칙 집합입니다. 모든 Dockerfile/Compose 의미·성능을 검증하는 빌드 시스템이 아닙니다. 미지원 구문은 정상/결함으로 단정하지 않습니다. 파일 수집 완료와 전체 검토 완료도 다릅니다.
2. 자동 diff는 검증된 .dockerignore 부재 추가부터 지원합니다. 소스 COPY/pip 재배치, 임의 Dockerfile 수정·배포는 추가 근거와 별도 구현/승인이 필요합니다. 기존 2단계 승인·hash·identity 검사는 유지합니다.
3. 실제 검증 환경의 서비스 컨테이너는 부재/중지 상태입니다. running/healthy/unhealthy/OOM·통신 실패·파일 drift는 자동 테스트의 실패 주입과 별도 실기 기록을 구분해야 합니다. 이 작업에서 업무 스택을 기동하거나 배포 승인 실행을 시험하지 않았습니다.
4. Linux/Windows/원격 엔진의 실기 호환성을 주장하지 않습니다. 보안 파일 접근은 기존 POSIX FD/O_NOFOLLOW 지원이 필요합니다. 다른 PC에서도 서버가 연결한 Docker와 선택한 경로를 조회하며 브라우저 PC의 Docker를 직접 읽는 것은 아닙니다.
5. 여러 Docker/파일 관측 전체가 원자적 스냅샷인 것은 아닙니다. 외부에서 환경을 바꾸면 측정 시점 차이가 생길 수 있습니다. 변경 승인에는 기존 hash·컨테이너 identity 재검증이 적용됩니다.
6. 과거 ai 9.99초/frontend 17.59초는 단일 참고 기록입니다. 같은 사전 변경 버전을 다시 실행한 paired baseline이 없으므로 최종 P50/P95를 공개하더라도 통제된 30% 성능 개선을 달성했다고 주장하지 않습니다.
7. 모델이 새로운 표현에서 오분류할 가능성은 남습니다. 이번 평가 통과는 동결된 집합에 대한 결과이며 모든 자연어에 대한 정확도·운영 위임 보장이 아닙니다.
